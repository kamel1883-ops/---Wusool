# وصول · Wusool

منصة SaaS تسويقية متعددة العملاء (**Multi-Tenant**) للشركات، مبنية على أساس قابل للتوسع:
عزل بيانات كل عميل، صلاحيات دقيقة، اشتراك سنوي بدفع يدوي معتمد، واعتماد بشري إلزامي قبل أي نشر
أو إرسال خارجي.

> **الحالة:** الأساس (حسابات، شركات، صلاحيات، اشتراك يدوي، فوترة، تدقيق) + تحليل المواقع
> واعتماد بشري + اكتشاف العملاء وCRM + الحسابات الاجتماعية والنشر والجدولة + القياس الداخلي
> والبوسترات ولوحة النتائج. ما يحتاج مزوّدًا أو مراجعة يظهر بحالته الصريحة ولا يُدّعى أنه يعمل.
> الحالة التفصيلية لكل مرحلة: [`docs/implementation-status.md`](docs/implementation-status.md).
> راجع أيضًا [`docs/roadmap.md`](docs/roadmap.md) و[`docs/social-channels.md`](docs/social-channels.md).

## المرحلة الثانية — تحليل المواقع

| المجال | التفاصيل |
| --- | --- |
| الرابط والمهمة | تحقق من الرابط (رفض loopback والشبكات الخاصة)، موافقة صريحة، وحالات `draft → queued → crawling → extracting → analyzing → awaiting_review → approved / changes_requested / failed / cancelled` |
| الزحف | `SiteCrawlerProvider`: `mock` للتطوير، `fetch` زاحف حقيقي داخل الـ Worker (نطاق واحد، robots.txt، حدود صفحات/عمق، مهلة، سقف حجم، لا تجاوز حماية)، و`cloudflare` هيكل جاهز |
| الذكاء الاصطناعي | `AIProvider`: `MockAIProvider` حتمي و`OpenAIProvider` متوافق مع OpenAI. الاختيار من الخادم، المفتاح في الأسرار فقط |
| الحسابات والقنوات | OAuth رسمي لكل شركة (Meta: Pages + Instagram، Google: GA4/Search Console/GTM/Business Profile discovery)، رموز مشفّرة AES-GCM على الخادم، مصفوفة قدرات لكل منصة، مكتبة منشورات بنسخ واعتماد، طابور نشر بمهمة واحدة لكل هدف وBackoff، وسجل نشاط — التفاصيل في [`docs/social-channels.md`](docs/social-channels.md) |
| اكتساب العملاء | ICP من التحليل المعتمد + عملاء بدليل ومصدر + درجات تأهيل + موافقة ومنع تواصل + حملات بفحص جاهزية + نتائج يدوية. كل ناتج اكتشاف يُحفظ **عميلًا محتملًا** (`classification = potential`, `stage = new`) بدرجة تطابق مفسّرة مع نشاط العميل، ولا يصبح «مُتحقَّقًا» إلا بتغيير بشري للمرحلة أو تسجيل موافقة. الاكتشاف الآلي له مسارَان: **OpenStreetMap مفعّل افتراضيًا بلا مفاتيح** (استعلام Overpass واحد محدود داخل مدينة سعودية من الملف، مع إسناد ODbL لكل سجل؛ `LEAD_DATA_PROVIDER=openstreetmap` صراحةً أو تركه فارغًا يعطي نفس النتيجة)، أو مزوّد مرخّص (`LEAD_DATA_PROVIDER`, `LEAD_DATA_API_URL`, `LEAD_DATA_API_KEY`) |
| التقرير | ٢٣ قسمًا (بيانات الشركة، الرسالة، الرؤية، القيم، الخدمات، الجمهور، الشخصيات، القيمة المقترحة، القنوات، الحملات، الخارطة، المؤشرات، النواقص، الافتراضات) وكل معلومة بمصدرها `website/inference/missing` ودرجة ثقتها |
| الاعتماد | نسخ غير قابلة للاستبدال، `submit-review`، `request-changes`، `approve` (مالك الشركة)، وتعديل المعتمد يعيده للمراجعة |
| الإدارة | متابعة المهام، إعادة تشغيل، إلغاء، حدود التحليل (صفحات/عمق/تزامن/سعر الساعة)، أخطاء تقنية واستهلاك المزوّدين — بلا محتوى تقرير العميل |
| الاختبارات | `tests/phase2.test.mjs` — ٦٧ فحص تكامل عبر HTTP على قاعدة جديدة (عزل، صلاحيات، اشتراك، حالات، نسخ، اعتماد، حدود، فشل/إعادة محاولة، تدقيق، عدم تسريب مفاتيح) |

### التشغيل

```bash
npm install
npm run db:migrate          # 0001 + 0002 على D1 المحلي
npm run dev:api             # Worker على 8787
npm run dev:web             # الواجهة على 3000
npm run check && npm run build && npm test
```

> الوضع الافتراضي **تجريبي** (`mock` للزحف والذكاء الاصطناعي): لا يحتاج أي مفاتيح، والواجهة
> تعرض ذلك بوضوح. للانتقال إلى مزوّد حقيقي أضف أسرار العامل (`AI_PROVIDER`, `AI_MODEL`,
> `AI_API_KEY`, `AI_GATEWAY_URL`, `CRAWLER_PROVIDER`, `CRAWLER_ACCOUNT_ID`.
> اكتشاف العملاء مفعّل افتراضيًا بلا مفاتيح (بيانات OpenStreetMap المفتوحة
> عبر Overpass، ترخيص ODbL، استعلام واحد لكل تشغيل داخل نطاق مدينة سعودية؛ ويمكن تثبيته صراحةً بـ `LEAD_DATA_PROVIDER=openstreetmap`). `LEAD_DATA_API_URL`
> اختياري لتوجيه الطلبات إلى مرآة Overpass أو نسخة داخلية عند انشغال الخدمة العامة. التشغيل
> محكوم بمهلة وحد أقصى للعناصر وبفاصل زمني لكل شركة (`LEAD_DISCOVERY_COOLDOWN_SECONDS`، افتراضيًا ١٥ ثانية).
> قنوات الحملات: البريد فقط عبر `EMAIL_PROVIDER`/`EMAIL_API_KEY`/`EMAIL_FROM` (Resend، منفّذ).
> أما `WHATSAPP_TOKEN` و`META_PAGE_TOKEN` و`META_PAGE_ID` و`LINKEDIN_TOKEN` فهي مسار قديم
> لرمز ثابت أحادي الحساب — **لا تزوّدها**: إرسال WhatsApp/Meta/LinkedIn من الحملات غير مكتمل،
> والنشر الاجتماعي متعدد العملاء يتم حصرًا عبر ربط OAuth لكل شركة من صفحة «الحسابات والقنوات».
> أسماء الأسرار لا تظهر للعميل أبدًا. لا يوجد إرسال بلا اعتماد محتوى وفحص جاهزية.
> `CRAWLER_API_TOKEN`) وبدّل المزوّد من إعدادات المنصة. لا يُرسل أي مفتاح إلى المتصفح.

## ما تم تنفيذه في هذه النسخة

| المجال | التفاصيل |
| --- | --- |
| الحسابات | تسجيل دخول بالبريد وكلمة المرور، PBKDF2-SHA256، جلسات بتوكن عشوائي مخزّن كـ Hash، إلغاء الجلسات عند التعطيل/التعليق |
| التهيئة الأولى | شاشة `/setup` تُنشئ أول Super Admin مرة واحدة فقط — لا كلمات مرور مكتوبة في الكود |
| تعدد العملاء | جدول `companies` + `memberships`، وكل استعلام للعميل مقيّد بعضوية المستخدم لا بمدخلات الطلب |
| الصلاحيات | ٥ أدوار داخل الشركة + Super Admin، تُفرض على الخادم في كل مسار |
| لوحة Super Admin | الشركات، الاشتراكات، الحالات، الفواتير، مراجعة إثباتات التحويل، الخطط والأسعار، المستخدمون، الاستخدام، سجلات النظام، إعدادات المنصة والهوية |
| مساحة العميل | لوحة تحكم، بيانات الشركة، الفريق، الاشتراك والفواتير (رفع إثبات التحويل)، الإعدادات، سجل النشاط |
| الاشتراك السنوي | حالات `Pending / Active / Suspended / Expired / Cancelled` + احتساب الانتهاء تلقائيًا + تنبيه قبل الانتهاء |
| الفوترة اليدوية | فاتورة برقم تسلسلي، رفع إثبات (PNG/JPG/PDF حتى ٥MB)، مراجعة (اعتماد/رفض)، اعتماد التحويل يفعّل الاشتراك ويحدّث تواريخه |
| الملفات | R2 خاص؛ لا يوجد أي مسار عام للملفات — كل قراءة تمر بصلاحية على الخادم |
| التدقيق | `audit_logs` لكل عملية حساسة: من فعلها، ومتى، وعلى أي كيان |
| اللغات | عربي (RTL) افتراضيًا وإنجليزي (LTR) مع تبديل فوري وحفظ التفضيل |
| الهوية | اسم المنصة والألوان والشعار وبيانات الدعم والحساب البنكي كلها **بيانات** في `platform_settings` تُدار من لوحة الإدارة |
| الأمان | رؤوس أمان، فحص Origin + ترويسة عميل لكل طلب تعديل، تحقق من الملفات، حد لعدد محاولات الدخول، منع تعطيل/تخفيض النفس، منع إزالة آخر مالك |

## التشغيل محليًا

```bash
npm install

# 1) قاعدة البيانات المحلية (D1)
npm run db:migrate

# 2) واجهة API على 8787 (Worker + D1 + R2 محليًا)
npm run dev:api

# 3) الواجهة على 3000 في طرفية ثانية
npm run dev:web
```

ثم افتح `http://localhost:3000`:

1. **`/setup`** — أنشئ أول حساب Super Admin (هذه الشاشة تظهر مرة واحدة فقط).
2. من **إعدادات المنصة** أدخل بيانات الدعم والحساب البنكي وبيانات الشركة المالكة
   (تبقى فارغة حتى تُعتمد — لا بريد أو نطاق تجريبي).
3. من **الشركات والعملاء** أنشئ شركة، وحدد الخطة وتواريخ الاشتراك، وستظهر كلمة مرور مؤقتة لمالكها.
4. سجّل دخول المالك، غيّر كلمة المرور، ثم من **الاشتراك والفواتير** ارفع إثبات التحويل.
5. من حساب Super Admin اعتمد الإثبات — يتم تفعيل الاشتراك تلقائيًا.

## البنية التقنية

- **الواجهة**: React 18 + TypeScript + React Router + Vite، بلا مكتبة UI خارجية (CSS خاص
  بمتغيرات هوية قابلة للتغيير من لوحة الإدارة).
- **الـ API**: Cloudflare Worker + Hono + TypeScript.
- **التخزين**: Cloudflare D1 (SQLite) للبيانات، وR2 خاص للملفات الحساسة.
- **الاستضافة**: Freebuff Sites (Worker + Assets + D1 + R2) على https://wusool.freebuff.page —
  النشر يدوي مُصرَّح به فقط، ولا أي مفاتيح سرية في الواجهة.

التفاصيل: [`docs/architecture.md`](docs/architecture.md) · نموذج البيانات:

## ملاحظات صريحة

- **النشر حي** على `https://wusool.freebuff.page` (بيئة الإنتاج، D1 + R2 مُرفقة). أي نشر جديد
  يتطلب بناءً وفحوصات خضراء أولًا.
- **البريد منفّذ عبر Resend** ويحتاج `EMAIL_API_KEY` + `EMAIL_FROM` ليُرسل. **لا إرسال WhatsApp
  ولا نشر اجتماعي من الحملات** — النشر الاجتماعي يتم حصرًا عبر ربط OAuth لكل شركة من صفحة
  «الحسابات والقنوات»، ولا تُزوَّد الرموز الثابتة القديمة (`META_PAGE_TOKEN` وغيرها).
- **الأسعار في الخطط تبدأ صفرًا** = «تُحدد عند العرض»، تُدخل من لوحة الإدارة ولا تُخترع.
- **قيم الهوية الحالية** مأخوذة من الشعار المرفق (كحلي `#0E1B2D` + تركوازي `#17C6B4`)، وقابلة
  للتغيير من الإعدادات.
