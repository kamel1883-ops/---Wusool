# تدقيق التكامل الحي — وصول / Wusool

**تاريخ التدقيق:** 2026-11-16 · **النطاق:** المنصة المنشورة على https://wusool.freebuff.page والكود في هذا المستودع
**نوع التدقيق:** اختبار فقط — لم تُضف تكاملات، ولم تُنشأ بيانات عملاء أو تحليلات وهمية، ولم تُغيَّر بيانات الإنتاج.

---

## ١. الخلاصة في عشرة أسطر

1. **لا يوجد تكامل واحد يعمل حيًّا على حساب حقيقي**، لأن بيئة الإنتاج لا تحتوي أي مفاتيح Meta/Google ولا مفتاح تشفير الرموز ولا سر مُشغّل المهام.
2. كل ما يلي **مُختبَر على محاكاة محلية** لنقاط المزوّدين، بكود النشر الحقيقي نفسه — وليس ادعاء اتصال.
3. الحسابات والأدوار والعزل والاعتماد والطابور وإدارة النسخ: تعمل ومُختبَرة آليًا.
4. Google: **الربط والاكتشاف فقط**. لا قراءة لبيانات GA4 أو Search Console أو Business Profile أو حاويات GTM — لا يوجد كود لذلك أصلًا.
5. Business Profile: النشر غير منفّذ، والمنشور يُحجب حتى قبل الاعتماد، ولا توجد قراءة للمشاهدات/المكالمات/طلبات الاتجاه.
6. المنشورات: الرفض و«طلب تعديلات» **غير منفّذين** (لا مسار API)، والاسترجاع لنسخة سابقة غير منفّذ.
7. الجدولة **تُحفظ فقط**: لا Cron على هذه الاستضافة، والمسار الداخلي يعيد 503 في الإنتاج.
8. التقارير: كل الأرقام **يدوية** (`source = manual`) أو غير متاحة؛ لا رقم يُخترع، وROI/CPL يظهران `null` بلا بيانات.
9. عثر التدقيق على **ثمانية عيوب حقيقية** في المنتج (القسم ٨)، أهمها أن مسارات القنوات لا تفحص الاشتراك، وأن صورة Facebook تُهمَل بصمت.
10. تفعيل أي تكامل يحتاج منك: تطبيق Meta + مراجعة، مشروع Google + طلبات وصول، ومُشغّل دوري — التفاصيل في القسم ١٠.

## ٤. المنشورات والطابور — دورة كاملة مُختبَرة

منشور اختبار داخل شركة اختبار محلية، على محاكي Meta:

| الخطوة | النتيجة | التفصيل |
| --- | --- | --- |
| Draft | ✅ | `POST /posts` = 201 وحالة `draft` |
| Awaiting Approval | ✅ | `submit` نقلها إلى `awaiting_approval` |
| Approved | ✅ | `approve` سجّل المعتمد والوقت |
| Scheduled | ✅ (حفظ فقط) | موعد مستقبلي → `scheduled` + مهمة `pending` واحدة |
| Publishing → Published | ✅ | `publishing` أثناء التنفيذ ثم `published` مع `externalId` و`externalUrl` |
| Failed | ✅ | فشل المزوّد يُخزَّن `failed` مع `errorCode` و`errorMessage` |
| اعتماد المنشور | ✅ | ولا اعتماد قبل الإرسال (409) |
| رفض المنشور | ❌ **غير منفّذ** | `POST /posts/:id/reject` = 404 |
| طلب تعديلات | ❌ **غير منفّذ** | `POST /posts/:id/request-changes` = 404 (المتاح: إلغاء أو أرشفة) |
| نشر فوري | ✅ | مرة واحدة لكل هدف |
| جدولة | ✅ حفظ / ❌ تنفيذ تلقائي | لا Cron؛ `tick` = 503 في الإنتاج |
| إلغاء الجدولة | ✅ | المنشور `cancelled` والمهمة `cancelled` |
| إعادة المحاولة | ✅ | `attempts` يزيد، والمنشور المنشور لا يُلمس |
| فشل منصة ونجاح أخرى | ✅ | `partially_published`، Facebook `published` وInstagram `failed` |
| عدم إعادة نشر الناجحة | ✅ | عدد منشورات Facebook لم يزد في المحاولة الثانية |
| الحفظ بعد إغلاق المتصفح | ✅ | إعادة تشغيل Worker + جلسة جديدة → المنشور وحالته موجودان |
| حفظ النسخ السابقة | ✅ جزئيًا | نسخة عند الإنشاء/كل تعديل/النسخ؛ تُعرض كـ(رقم، سبب، وقت) فقط، والمحتوى المحفوظ لا يُعاد |
| استرجاع نسخة سابقة | ❌ غير منفّذ | `POST /posts/:id/restore` = 404 |
| منع تعديل المنشور المنشور | ✅ | 409 `post_already_published` |
| نسخة جديدة عند التعديل | ✅ | `duplicate` = 201 منشور جديد `draft` |
| تسجيل الرابط الخارجي | ✅ | Facebook: يُبنى من المعرّف · Instagram: يُجلب `permalink` |
| تسجيل وقت النشر | ✅ | `publishedAt` |
| تسجيل سبب الفشل | ✅ | `errorCode` + `errorMessage` + حدث في `social_events` |
| تعديل منشور معتمد | ✅ | يعيده إلى `draft` ويمسح الاعتماد (يتطلب اعتمادًا جديدًا) |

**بخصوص الجدولة صراحةً:** الجدولة **محفوظة فقط**. لا يوجد مُشغّل دوري على استضافة Sites، والمسار الداخلي `POST /api/internal/social/tick` يعيد **503 `scheduler_not_configured`** على الإنتاج الآن. التنفيذ ممكن يدويًا من داخل الشركة («تشغيل المستحق الآن») أو عند ربط مُشغّل خارجي بسر مشترك.

## ٩. ما لا تدعمه الاستضافة أو الواجهات الرسمية

| القيد | النوع | التفصيل |

## ١٠. خطوات التفعيل التالية

### ما المطلوب منك تحديدًا

1. **Meta**: إنشاء تطبيق أعمال، إضافة المنتج (Facebook Login + Pages API + Instagram Graph)، تعيين `META_APP_ID` و`META_APP_SECRET` و`META_REDIRECT_URI` في Secrets، ثم Business Verification وApp Review لـ`pages_manage_posts` و`instagram_content_publish` إن أردت خدمة حسابات لا تملكها.
2. **Google Cloud**: مشروع واحد + تفعيل Analytics Admin API وSearch Console API وTag Manager API، شاشة موافقة OAuth، ثم `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` و`GOOGLE_REDIRECT_URI`.
3. **Google Business Profile**: تقديم طلب وصول للـBusiness Profile APIs (منفصل عن الخطوة ٢).
4. **مفتاح تشفير الرموز**: أنشئ سرًّا عشوائيًا 32 بايت base64 مرة واحدة (`openssl rand -base64 32`) وضعه في `SOCIAL_TOKEN_KEY` — لا ترسله في المحادثة.
5. **قرار الجدولة**: إما خطة Workers مدفوعة مع Cron Trigger، أو مُشغّل خارجي يستدعي `POST /api/internal/social/tick` بـ`JOBS_SECRET`.
6. **حساب اختبار رسمي** لكل منصة (صفحة + حساب Instagram احترافي مرتبط + خاصية GA4 + موقع Search Console) لإجراء اختبار حي.
7. **قرار نطاق المرحلة**: هل نصلح العيوب 1–10 أولًا أم نربط المفاتيح ونختبر الحي كما هو؟

### ما المطلوب من Freebuff برمجيًا

1. حاجز الاشتراك على مسارات القنوات (عيب ١).
2. نشر وسائط Facebook أو حجبها صراحةً (عيب ٢).
3. قراءة بيانات GA4/GSC/insights مع وسم `source` لكل رقم، أو إزالة ادعاء القدرة (عيوب ٣، ٩، ١٠).
4. تصحيح اكتشاف Business Profile وإنشاء منشوراته (عيوب ٥، ٦).
5. `social.` في مفاتيح الإعدادات (عيب ٤).
6. `reject` و`request-changes` واسترجاع النسخ (عيوب ٧، ٨).
7. مهمة سحب قياس دورية + عدّاد حد Instagram.
8. بعد إصلاح ما سبق: إعادة تدقيق مع مفاتيح حقيقية وتسجيل النتائج هنا بتاريخ جديد.
