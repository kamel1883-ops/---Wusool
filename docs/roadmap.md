# خطة المراحل والافتراضات

## ١. المراحل

### ✅ المرحلة الأولى — الأساس (منجزة في هذه النسخة)
- حسابات، تسجيل دخول، جلسات آمنة، تغيير كلمة مرور إلزامي عند أول دخول.
- شركات (مستأجرون) وعضويات وأدوار وصلاحيات مفروضة على الخادم.
- عزل بيانات كامل ومُختبر بين شركتين.
- لوحة Super Admin: شركات، خطط، اشتراكات، فواتير، إثباتات تحويل، مستخدمون، استخدام، سجلات، إعدادات.
- اشتراك سنوي بحالات خمس، تنبيه انتهاء، تعليق يلغي الجلسات فورًا.
- فوترة يدوية عبر تحويل بنكي + رفع إثبات + مراجعة + تفعيل تلقائي.
- عربي/إنجليزي مع RTL/LTR، وهوية بصرية من قاعدة البيانات.
- سجل تدقيق لكل عملية حساسة.

### المرحلة الثانية — تحليل الموقع
- إدخال الرابط، تحقق، احترام `robots.txt`، عدم تجاوز حماية أو CAPTCHA، عدم دخول صفحات محمية.
- حالات المهمة: `Queued → Crawling → Extracting → Analyzing → Completed/Failed` مع إعادة المحاولة.
- استخراج الأقسام الـ١٥ المطلوبة مع تصنيف كل حقل (مستخرج/استنتاج/اقتراح/غير متوفر).
- محرر نتائج: تعديل/قبول/رفض/إعادة تحليل/ملاحظات، ثم اعتماد نسخة نهائية.
- تسجيل الصفحات الناجحة والفاشلة وتاريخ التحليل.

### المرحلة الثالثة — الاستراتيجية والمحتوى
- استراتيجية وخارطة طريق وقنوات ومؤشرات، مبنية على التحليل المعتمد فقط.
- حملات بحالاتها الثماني، ومحتوى ثنائي اللغة بأنواعه، ونسخ متعددة بلا استبدال.
- سير الاعتماد `Draft → In Review → Changes Requested → Approved → Scheduled → Published`.
- طبقة `AiProvider` قابلة للتبديل (OpenAI/Anthropic/Gemini/Llama/Workers AI/OpenAI-compatible)
  مع Mock في التطوير، وتسجيل كل استدعاء في `usage_events`.

### المرحلة الرابعة — الصور والبوسترات
- مقاسات: مربع، Portrait، Story، Banner، LinkedIn، WhatsApp، PDF لاحقًا.
- قوالب + هوية العميل (شعار/ألوان/خطوط) + نص عربي كطبقة تصميم منفصلة لضمان القراءة.
- نسخ متعددة، تعديل، مراجعة، اعتماد، تنزيل.

### المرحلة الخامسة — CRM والتواصل
- عملاء محتملون بمراحلهم التسع، مصدر، حملة، درجة، آخر تواصل، موعد متابعة، سجل نشاط.
- موافقة تواصل صريحة + قائمة منع تواصل (Suppression).
- بريد وWhatsApp عبر مزوّد رسمي فقط، قوالب، جدولة، Webhooks، تتبع حالة، إلغاء اشتراك.
- **وضع تجريبي يمنع الإرسال الحقيقي** حتى إعداد المزوّد والمفاتيح.

### المرحلة السادسة — التقارير والتوسع
- تقارير تفصل: ما أنشأه الذكاء الاصطناعي / ما اعتمده الفريق / ما أُرسل / ما نُشر / ما نتج عنه تفاعل.
- استهلاك وتكاليف الذكاء الاصطناعي، تحسين التكلفة، حدود حماية لكل عميل.
- تجهيز مزوّد دفع سعودي (المفاتيح والواجهات فقط)، النطاق والبريد الرسمي، تحسين الأمان والأداء.

## ٢. الافتراضات التي تحتاج تأكيدًا منك

| # | الافتراض الحالي | يلزم قرارك |
| --- | --- | --- |
| 1 | اسم المنصة «وصول / Wusool» وألوان الشعار (كحلي + تركوازي) | تأكيد الاسم النهائي والألوان |
| 2 | خطة الدفع سنوية فقط، والدفع يدوي (تحويل بنكي) في المرحلة الأولى | تأكيد أن الاشتراك سنوي دائمًا أو إضافة شهري |
| 3 | خطة «الانطلاق/النمو/المؤسسات» أسماء مبدئية بأسعار صفر | تحديد الأسماء والأسعار والمزايا الفعلية |
| 4 | أول حساب Super Admin يُنشأ من `/setup` بحسابك | من سيكون المالك؟ (لا تُرسل كلمة مرور في المحادثة) |
| 5 | الدعوات بكلمة مرور مؤقتة تُعرض مرة واحدة (لا بريد دعوة) | تأكيد القبول، أو توفير مزوّد بريد لاحقًا |
| 6 | منطقة افتراضية للسوق السعودي، عملة SAR، تواريخ ميلادية | تأكيد العملة والتقويم (هجري؟) |
| 7 | بيانات الشركة المالكة (السجل التجاري، الرقم الضريبي، IBAN) تبقى فارغة حتى تُعتمد | تزويدها من لوحة الإدارة عند جاهزيتها |
| 8 | حذف الشركة نهائيًا (مع ملفاتها) من لوحة الإدارة | هل تريد أرشفة بدل الحذف النهائي؟ |
| 9 | حد إضافة الأعضاء يتبع حالة الاشتراك فقط | هل تريد حدودًا رقمية لكل خطة (`max_users`)؟ |
| 10 | سياسة الخصوصية والشروط نص أولي | مراجعة قانونية قبل الإطلاق |

## ٣. ما يعمل الآن بلا أي مفاتيح خارجية

- كل شيء في المرحلة الأولى: الحسابات، الصلاحيات، العزل، الاشتراكات، الفواتير، إثباتات التحويل
  (تخزين R2)، التدقيق، الهوية، اللغتان.
- لا يحتاج تشغيله أي مفتاح API؛ ولا يوجد أي إرسال بريد/WhatsApp أو استدعاء نموذج.

## ٤. ما يتطلب مفاتيح أو بيانات قبل تفعيله

| الخدمة | ما يلزم | أين تُحفظ |
| --- | --- | --- |
| مزوّد ذكاء اصطناعي (المرحلة ٣) | مفتاح + اسم النموذج + حدود | Secrets على الخادم، إعدادات المزوّد في قاعدة البيانات |
| بريد المعاملات (الدعوات/الاستعادة) | مزوّد + دومين موثّق + مفتاح | Secrets |
| WhatsApp Business API | حساب أعمال معتمد + قالب معتمد + توكن | Secrets |
| بوابة دفع سعودية (المرحلة ٦) | حساب تاجر + مفاتيح | Secrets |
| النطاق والبريد الرسمي | دومين + DNS | إعدادات المنصة |

> لا تُدخل أي مفتاح في الواجهة أو الكود أو ملفات المستودع. تُضاف كأسرار على الخادم
> (على Sites: Settings → Secrets) وتُقرأ داخل الـ Worker فقط.

## ٥. قواعد غير قابلة للتفاوض في المراحل القادمة

1. لا نشر أو إرسال خارجي قبل `Approved` من مستخدم مخوّل، ويسجَّل من اعتمد ومتى وأي نسخة.
2. لا اختراع بيانات: كل حقل في نتائج التحليل مصنّف المصدر، والناقص يُعرض «غير متوفر + سؤال للعميل».
3. لا استخراج من صفحات محمية أو عبر تجاوز CAPTCHA، واحترام `robots.txt`.
4. لا مفاتيح ولا أسرار في الواجهة أو الكود.
5. لا إرسال جماعي دون موافقة موثّقة، ودومًا مع إمكانية إلغاء الاشتراك.
6. لا ربط Google Ads أو Meta Ads ولا بوابة دفع قبل طلب صريح.
7. كل خدمة خارجية قابلة للتعطيل من لوحة الإدارة، مع Mock واضح في التطوير.
8. الحالات والحدود تُفرض على الخادم، لا في الواجهة فقط.
